# Sonus 0.4.0

CreeperUX Music 改名为 Sonus，并且有了跨设备控制（Sonus Connect）。

## 下载

| 文件 | 说明 |
|---|---|
| `Sonus-0.4.0-x64-setup.exe` | 安装程序，普通 Intel / AMD 电脑（推荐） |
| `Sonus-0.4.0-ARM64-setup.exe` | 安装程序，骁龙等 ARM 电脑（推荐） |
| `Sonus-0.4.0-x64.msi`、`Sonus-0.4.0-ARM64.msi` | 和安装程序里装的是同一个 MSI |
| `CreeperUX-Music-0.4.0-x64-setup.exe`、`CreeperUX-Music-0.4.0-ARM64-setup.exe` | 和上面的安装程序完全相同，只是用了旧名字：0.3.0 按这个名字找更新 |

只为当前用户安装，不需要管理员权限，装在 `%LOCALAPPDATA%\Programs\Sonus`，开始菜单里的快捷方式叫「Sonus」。安装程序没有数字签名，第一次运行时 SmartScreen 可能会提示，选「更多信息 › 仍要运行」。

## 改名为 Sonus

- 0.3 及更早的版本叫 CreeperUX Music。Sonus 是拉丁语的“声音”，和 Lumen（光）是一对。
- 从 0.3.0 升级：在程序里点「新版本」，或者直接运行新的安装程序。新版本会替换旧版本，不会并排装两个。
- Sonus 第一次启动时会自动接手旧版本留下的东西，所以不用重新登录，也不用重填 GitHub 令牌：
  - 数据目录从 `%LOCALAPPDATA%\CreeperUX Music` 搬到 `%LOCALAPPDATA%\Sonus`。
  - 凭据管理器里的 `CreeperUXMusic:server`、`CreeperUXMusic:github` 改存为 `Sonus:server`、`Sonus:github`。
- 固定在任务栏上的旧图标指向已删除的旧程序，需要重新固定一次。
- 程序对服务器报的名字变成 `Sonus (<电脑名>)`，Navidrome 会多出一个播放器；旧的那条可以在 Navidrome 的「播放器」里删掉。
- GitHub 仓库的名字没变（CreeperUX/CreeperUX-Music），已有的只读令牌继续可用。

## 新功能：跨设备控制（Sonus Connect）

- 像 Spotify Connect 一样：播放条右侧的「设备」按钮列出同一账号下在线的设备，以及它们各自在放什么。
- 选中另一台设备后，播放条控制的就是那台：播放和暂停、上一首和下一首、拖动进度、音量，以及空格和 Ctrl + 方向键。
- 选中时如果这台正在播放，播放会转过去，对方从同一首歌、同一位置接着放，这边停下；选回「这台电脑」时同理。其他情况只遥控，不打断对方正在放的东西。
- 需要服务器支持，原版 Navidrome 没有这个功能：
  - 要用 CreeperUX 改版的 Navidrome，Docker 镜像是 `ghcr.io/creeperux/navidrome:latest`。
  - docker-compose 里只换 `image`，数据目录不变。改版不改数据库，换回原版镜像就能回退。
  - 用原版服务器时设备按钮不出现，其他功能不受影响。

## 测试情况

- 核心库测试 97 项全部通过。新增的测试覆盖跨设备控制，以及接手旧名字留下的数据。
- 静默端到端验收：
  - ARM64：77 / 77 通过。
  - x64：用 MSI 解出的程序跑。跨设备控制一轮里有一处测试脚本等待条件不对，修正后这一轮重跑通过。
  - 新增「从 CreeperUX Music 升级」一轮：在旧名字下存好登录和令牌，启动后自动搬过来，不用重新登录，令牌也能直接检查更新。
- 跨设备控制改名前对本地编译的改版 Navidrome 验证过：真实登录，两个程序实例互相看见。改名后，改版的 Go 测试全部通过，新镜像已构建好。
- 安装包：
  - 两个 MSI 都只解包、不安装，再用解出的程序跑验收。
  - 安装程序的每一页都离屏画出来检查过。
  - 内嵌的 MSI 和单独的 MSI 一致，旧名字的安装程序和新名字的逐字节相同。
- 没有在电脑上真正安装过，也没有真正从 0.3.0 升级过：请你自己试一次，确认升级后不用重新登录。

## 已知限制

- 安装程序没有数字签名。
- 界面只有中文。
- 跨设备控制目前只有 Sonus（Windows）支持，手机上还没有。
