# Sonus 安卓版 0.2.1（测试版）

修正一个登录问题：服务器地址会跳转时（例如反向代理把所有 `http://` 请求都 301 跳到 `https://`），「在浏览器中登录」失败，提示「服务器没有开始登录（401）」。

## 下载

附件里的 APK 是测试版：装上后叫「Sonus 测试版」（包名 `com.creeperux.sonus.debug`，版本 0.2.1），需要 Android 13 及以上，可以直接覆盖安装 0.2.0。用调试密钥签名，还没有正式版的签名密钥。

## 修正

- **地址会跳转时，用跳转后的地址。** 以前 App 检查服务器时跟着跳转走通了，却仍记着原来的 `http://` 地址；之后发起浏览器登录的 POST 请求遇到 301，被网络库改成了不带内容的 GET，服务器回 401。现在检查服务器、用户名密码登录、浏览器登录都会改用跳转后的地址，以后的请求（包括播放和封面）也都发到那里。登录页上的地址会换成实际用的那个，所以「互联网上的 HTTP 地址」提醒也会消失。已经用 0.2.0 登录、记着旧地址的，下次连上服务器时也会自动换成跳转后的地址。
- **POST 请求不再被悄悄改成 GET。** 遇到跳转时，App 把同一个 POST（连同内容）重新发到跳转后的地址，就像 307/308 跳转那样。只在同一台主机上这样做（允许从 `http://` 升到 `https://`）；跳到别的主机或从 `https://` 降到 `http://` 时不跟，并明确提示「服务器把请求从…转到了…，Sonus 没有跟过去」，不再显示让人摸不着头脑的 401。

## Windows 版

Windows 版的 `Sonus.Core` 有同样的问题（.NET 的 HttpClient 遇到 301/302 也会把 POST 改成 GET），同一处一起修了：探测、密码登录、浏览器登录改用跳转后的地址，POST 遇到跳转会原样重发。这会随下一个 Windows 版本发布；Windows 登录页上显示的地址这次没有改（那部分在 `src/Sonus` 里，另一个会话正在改那里）。

## 测试情况

- 安卓：电脑上的测试 71 项全部通过，其中新增 8 项。新增的测试在本机起一个小前端，把所有请求 301 跳到演示服务器（换了端口，就像 `http://` 跳到 `https://` 换了地址）：检查服务器、浏览器登录（开始、等待批准、拿到密钥、撤销密钥）、用户名密码登录、记着旧地址的登录自动换地址、表单 POST（新建歌单）都能穿过跳转；302、307 也能；跳到别的主机时给出明确提示。把修正去掉再跑，其中 4 项失败（演示服务器对被改成 GET 的请求回 422，正式服务器回 401）。
- 安卓模拟器（手机，静默）：把服务器地址填成跳转前端，跑设备测试：用户名密码登录、浏览器登录（拿到密钥、退出时交还）、播放和后台播放都通过；浏览器登录时显示的批准页地址是跳转后的地址。
- Windows：`Sonus.Core` 测试 133 项全部通过，其中新增 19 项（同样的跳转前端）；去掉修正后其中 5 项失败。

**还没有验证的：**

- 没有在真实手机上、也没有对正式服务器试过（按要求只用本机的演示服务器）。正式服务器的 `http://` → `https://` 跳转和测试里的「换端口」是同一类情况，但真正的 TLS 证书和反向代理没有在测试里出现。
- Windows 程序本身（`src/Sonus`）没有跑验收，只跑了 `Sonus.Core` 的测试。
