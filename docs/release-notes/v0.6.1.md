# Sonus 0.6.1

修正 0.6.0 播放中的三个错误：一首歌自己放完、无缝接上下一首后，新歌沿用了上一首的长度；从歌曲中间接着放（换设备、在另一台上按播放）时，实际从两倍的位置开始；以及一首刚开始播放的歌偶尔被当成「放不了」跳过。

## 下载

| 文件 | 说明 |
|---|---|
| `Sonus-0.6.1-x64-setup.exe` | 安装程序，普通 Intel / AMD 电脑（推荐） |
| `Sonus-0.6.1-ARM64-setup.exe` | 安装程序，骁龙等 ARM 电脑（推荐） |
| `Sonus-0.6.1-x64.msi`、`Sonus-0.6.1-ARM64.msi` | 和安装程序里装的是同一个 MSI |
| `CreeperUX-Music-0.6.1-x64-setup.exe`、`CreeperUX-Music-0.6.1-ARM64-setup.exe` | 和上面的安装程序完全相同，只是用了旧名字：0.3.0 按这个名字找更新 |

只为当前用户安装，不需要管理员权限，装在 `%LOCALAPPDATA%\Programs\Sonus`。安装程序没有数字签名，第一次运行时 SmartScreen 可能会提示，选「更多信息 › 仍要运行」。

## 修正

- **无缝换歌后，新歌用了上一首的长度。** 一首歌自己放完、接着放下一首时，Windows 播放器有一会儿还报告上一首的长度，程序照搬了它，并把它报给了服务器。服务器按这个长度截住进度，于是所有设备上的进度条都停在上一首的长度（比如放《ETERNAL WIND》时停在 3:50，那是上一首《Into the Sky》的长度）。现在程序只取当前这首自己的长度，报给服务器的长度优先用曲库里的。
- **从中间接着放时，实际从两倍的位置开始。** 把播放转到另一台设备、或在另一台上按播放接着放时，开始位置被设了两次，两次加在一起：从 1:30 接着放，实际从 3:00 开始；位置过了歌曲的一半，就直接越过结尾，跳到下一首。现在只设一次。
- **刚开始播放的歌被当成「放不了」跳过。** 播放器有一种出错通知不说是哪首歌，程序一律算在正在放的那首头上；刚换下来的那首（或预先载入的下一首）出错时，正在正常播放的歌就被报成「无法播放」并跳过。现在正在出声的歌不会再因此被跳过，每次出错都在日志里记下是哪首歌。上一条（越过结尾）在真实的音乐文件上很可能也表现为这样的「无法播放」。

## 服务器一侧

同一天的 Sonus 服务器镜像（`ghcr.io/creeperux/sonus-server`，`sha-14704b2`）也改了：

- 新歌的长度以服务器曲库里的为准，设备报来的长度只在曲库没有时才用。这样即使还有电脑在用 0.6.0、报错了长度，也不会再让所有设备的进度停住。
- 正在出声的设备报的位置照实采用，不再截在曲库长度以内：有些 MP3 实际比曲库记的长一两秒，截住会让歌放不到结尾。

## 测试情况

- 核心库测试 114 项、Connect 第 2 版的会话逻辑和演示服务器测试 28 项全部通过。
- 静默端到端验收，十四轮，对演示服务器，从源码构建的 ARM64 程序：93 / 93 通过（1 项跳过：第 1 版才有的「接着播放」提示）。演示服务器只提供第 1 版时，相关几轮（含播放）40 / 40 通过。
- 「跨设备控制」一轮新增一项：一首歌自己放完、无缝接上更长的下一首后，两台设备都显示新歌的长度，进度能走过上一首的长度。用 0.6.0 跑这一项会失败，修正后通过。
- 同一轮里「把播放转过来」现在发生在歌曲 2 分多钟处：0.6.0 在这里会直接跳到下一首，修正后从同一位置接着放。
- 用 MSI 解出的程序再跑十四轮：ARM64 和 x64（在 ARM 电脑上模拟运行）都是 93 / 93 通过（1 项跳过）。旧名字的安装程序和新名字的逐字节相同。
- 同样的十四轮对真正的 Sonus 服务器（含下面的服务器修正，53 首、每首 70 到 130 秒的测试曲库，一次性用户）：93 / 93 通过，4 项跳过（曲库里没有 DSD 歌曲；大封面在前几轮已经取过；第 1 版的「接着播放」提示；「单独切断一台设备的网络」只有演示服务器做得到）。新增的那项也通过。
- **还没有验证的**：
  - 「刚开始播放的歌被当成放不了」没能在演示服务器上重现。上面的两处修正是从代码和日志推断的，要在正式服务器和真实的音乐文件上再看。
  - 没有在两台真实的电脑上试过。
