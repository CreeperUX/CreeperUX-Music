# Sonus 网页版

Sonus 的浏览器界面：和 Windows 版同一套三栏版式（音乐库、页面、正在播放/队列、底部播放条），窄到手机宽度时换成底部标签加迷你播放条。纯静态文件，不需要构建：任何能发静态文件的服务器把这个文件夹原样发出去就能用。

```powershell
npm run demo:browser      # 启动演示服务器并打开浏览器（账号 demo / demo）
npm run check:web         # 验收：Chromium 和 WebKit，无界面
```

## 放到哪里、连哪台服务器

只需要改 [`config.js`](config.js) 一个文件：

| `server` | 含义 |
|---|---|
| `''`（默认） | 登录页让人填服务器地址。界面和服务器不在一处时用（演示服务器、桌面壳）。 |
| `'same-origin'` | 界面就是这台服务器发出来的（以后由 Rust 服务器在自己的路径下提供）。服务器不在根路径时，把路径写进 `base`。 |
| `'https://…'` | 固定连这台服务器，登录页不再问地址。 |

界面里的所有地址都是相对路径（`./src/…`、`./vendor/…`、`./assets/…`），路由在 `#` 后面，所以放在任何路径下都不用改别的。

## 登录的三种方式

1. **密码**（任何 Subsonic 服务器）：只保存由密码算出的令牌，不保存密码。
2. **密码加两步验证码**（Sonus 服务器）：开了两步验证后，账号密码不能直接用于播放接口。登录页用密码和验证码登录网页会话，并在同一次请求里让服务器为这个浏览器建一个“应用专用密码”（所以只要一个验证码），再用它登录。这个密码列在“账号与安全”里，可以随时撤销。服务器要求两步验证而账号还没设置时，登录页先要管理员给的一次性“绑定码”，然后才显示二维码。
3. **在浏览器中登录**（Sonus 服务器）：登录页显示一个代码，在已登录的页面（本界面的 `#/device`，或服务器自带的页面）里核对并允许，服务器发给这个浏览器一把自己的钥匙（API key）。退出登录时钥匙交还服务器。批准页会显示请求来自哪个应用、哪台设备、哪个地址；账号开了两步验证时，点“允许”还要输入验证码。

在“账号与安全”里新建应用专用密码，账号开了两步验证时同样要验证码。这些是 Sonus 服务器（Rust）在安全审查之后加的规则，见 `server/README.md` 的 “Codes a session alone does not replace”。

## 页面

| 路由 | 内容 |
|---|---|
| `#/` | 首页：问候、快捷磁贴、几排卡片 |
| `#/library/playlists` `albums` `artists` `songs` | 音乐库（手机上的“音乐库”标签） |
| `#/album/<id>` `#/artist/<id>` `#/playlist/<id>` | 专辑、艺人、歌单（自己的歌单可改名、排序、删歌、删除） |
| `#/search/<词>` `#/genre/<流派>` `#/shelf/<名>` | 搜索、流派、“显示全部” |
| `#/now` | 正在播放（手机上由迷你播放条打开）：封面、进度、控制、歌词 |
| `#/lyrics` | 全屏同步歌词 |
| `#/settings` | 播放、输出设备、账号、外观 |
| `#/account` | 账号与安全：两步验证、应用专用密码 |
| `#/device?code=…` | 批准另一个应用的“在浏览器中登录” |

键盘：空格 播放/暂停；Ctrl+←/→ 上一首/下一首；Ctrl+↑/↓ 音量；Ctrl+K 或 / 搜索；Alt+←/→ 后退/前进；Alt+Shift+B 喜欢。系统的媒体控制（键盘媒体键、锁屏、耳机按键）通过 Media Session 工作，包括进度。

## 代码怎么分

```
config.js            部署设置（上表）
src/app.js           启动、路由、把各部分接起来；自己不保存播放状态
src/api/contract.js  界面需要服务器和播放器提供的全部能力（“契约”）
src/api/subsonic.js  契约的实现：Subsonic/OpenSubsonic 接口 + 浏览器里的播放（两个 <audio>）
src/api/sonus.js     Sonus 服务器自己的接口：现在是 /auth，以后加 /sonus/v1
src/api/connect.js   Sonus Connect 第 2 版的会话状态（不碰浏览器，node 里也能跑）
src/api/session.js   Connect 的 WebSocket 连接：断线重连、命令与回执、退出时告别
src/shell/           外框：顶栏、音乐库侧栏、右侧面板、播放条、手机底栏、设备选择器（devices.js）
src/views/           各个页面，每个路由一个模块
vendor/creeperux-gui 界面零件库（照搬，不在这里改；见其中的 PATCHES.md）
```

界面只和“契约”打交道，从不直接请求服务器；所以换一种播放方式不用改页面。

## 为以后留的位置

## Sonus Connect（多设备同一个播放会话）

服务器提供 Connect 第 2 版时（`sonusConnect` 扩展里有版本 2，即 Sonus 服务器；协议见 `docs/protocol/connect.md`），一个账号只有一个播放会话，放在服务器上：

- 播放什么、队列、播放顺序、“播完这首停止”都是会话的。界面上的 `play`、`next`、`queueAdd`、`setOrder` 等契约方法变成发给会话的命令，`player`、`queue` 事件转述会话。页面不用管是哪种情况。
- 同一时间只有一台设备出声。这个浏览器是出声设备时，两个 `<audio>` 跟着会话走（加载、跳到位置、播放或暂停、预载下一首），并把真实发生的事报告给服务器；不是时就静音，进度按服务器的时钟往前走。
- 换出声设备只在设备选择器里（播放条右侧；手机上在“正在播放”页）。播放条下方的横条写着“正在「手机」上播放”，没有设备在放时写“上次在「书房电脑」播放”。
- 别的设备在放时，播放条的音量调的是那台设备的音量；每台设备的音量各自独立。
- 无法播放的歌由服务器跳过，并提示是哪一首；连续 5 首都不能播放就停下。
- 每个浏览器（同一个浏览器配置）是一台设备，编号存在本地。同一浏览器开两个标签页时，后打开的接管这台设备，先前那个静音；在先前那个按播放，又接管回来。
- 关闭页面时会向服务器告别（WebSocket 关闭码 1000），会话立即停在原处，别的设备可以马上接着放。

服务器不提供第 2 版时（例如原版 Navidrome），一切照旧：队列在这个浏览器里，暂停或关闭时把队列存到服务器（`savePlayQueue`），另一台设备打开时提示“接着上次听”。有会话时这两样不再使用。

测试：`node --test web/test/connect-vectors.test.mjs` 用协议的测试数据（`docs/protocol/connect-vectors.json`）逐步检查会话状态；`tools/check-web.mjs` 里有两个浏览器同时登录同一账号的一轮。

**管理后台**（用户、媒体库与扫描、服务器设置；等 `/sonus/v1` 设计出来）。`#/account` 是这块的第一页：新页面加在 `src/views/`，接口加在 `src/api/sonus.js`（已有带会话的 `call`），管理员身份从网页会话的 `isAdmin` 得到。网页会话只放在内存里，刷新后要重新输入密码。

## 验收检查了什么

`tools/check-web.mjs` 启动演示服务器，用真实浏览器操作界面，再从服务器一侧读回结果：登录（密码、浏览器登录、两步验证）、播放与队列、无缝切歌、计播放、Connect 的两台设备（显示另一台在放什么、遥控、切换出声设备、各自的音量、关闭后接着放）、喜欢、歌单增删改、音乐库页面、手机版式、键盘与系统媒体控制、跨源封面取色、账号与安全、设备批准；每个页面在七种版式（深浅主题、密度、宽度从手机到桌面、200% 缩放）下检查控制台错误、页面溢出和无障碍（axe，WCAG 2.1 A/AA）。

两步验证、应用专用密码和批准页对的是检查脚本里按服务器代码写的替身（演示服务器没有这些接口），还没有对真正的 Sonus 服务器跑过。
