# Sonus 安卓版 0.4.0（测试版）

应用内更新：以后的新版本在 App 里检查、下载、安装，不用再从电脑装。

## 下载

附件里的 APK 是测试版：装上后叫「Sonus 测试版」（包名 `com.creeperux.sonus.debug`，版本 0.4.0），需要 Android 13 及以上，可以直接覆盖安装 0.3.x，登录不丢。

**这一版还要手动装一次**（0.3.x 里没有更新功能）；从 0.4.0 起，之后的测试版在 App 里就能更新。

## 新功能

- **设置 › 更新。** 显示当前版本和上次检查的时间，可以点"检查更新"；有新版本时出现"安装更新"。可以关掉"启动时自动检查（每天一次）"。
- **每天自动检查一次。** 启动几秒后问一次 GitHub（一天最多一次；上次发现了新版本时每次启动都再问一次，免得重启后提示消失）。发现新版本时，设置按钮上出现一个小点，并提示一次"Sonus 0.4.1 可以更新了"，点"查看"进设置。
- **安装更新。** 面板里显示新版本号、大小、发布日期和更新说明，点"下载并安装"：
  1. 下载 APK，显示进度，可以取消；
  2. 按 GitHub 记录的 SHA-256 校验，再确认这个 APK 是 Sonus 测试版（包名）、比装着的新（versionCode）、签名和装着的一样，任何一项不对都删掉并说明原因；
  3. 第一次需要允许 Sonus "安装未知应用"（面板里有"去允许"按钮，打开系统设置，回来后自动继续）；
  4. 系统弹出"要更新此应用吗？"，确认后 Sonus 关闭、更新；在模拟器上更新完会自动重新打开，登录和设置都在。
  在系统确认框里点取消，面板显示"已取消安装。"，点"重试"不会重新下载。
- **只收自己那一路的版本。** 测试版只接收 GitHub 上标为预发布的 `android-v…-test.N`；以后的正式版（`com.creeperux.sonus`，正式签名）只接收正式发布的 `android-v…`。两者包名、签名都不同，不会互相覆盖。Windows 版的发布（`v0.6.2` 这类）不会被当成安卓版。
- 更新来源是 GitHub 上 Sonus 的公开仓库，不用登录，不发送任何账号信息。

## 测试情况

- 电脑上的测试：核心库 77 项（其中更新 11 项：读取发布列表、挑选版本、经跳转下载、SHA-256 不一致时删除、已下载的文件不重复下载、限流和 404 的提示、每天一次的规则）和 App 单元测试 13 项（其中更新 4 项：测试版找到测试版更新、不是有效 APK 的下载被拒绝并删除、安装结果的提示、更新说明的显示）全部通过。另有一项只在手动要求时读真的 GitHub：这次读了一次发布列表，读到 0.3.0 和 0.2.0 测试版及其 SHA-256。
- 模拟器上的完整流程（平板、手机各一遍）：装 0.4.0 → 指向这台电脑上的假 GitHub（发布了 0.4.1）→ 登录 → 自动检查发现 0.4.1，出现小点和提示 → 设置 › 更新 › 安装更新 → 下载并校验 → 允许安装未知应用 → 系统确认（手机上先取消一次，再重试，没有重新下载）→ 装上 0.4.1（versionCode 7），自动重新打开，登录还在，再检查显示已是最新。平板那遍发现"可以更新了"的提示条没有出来（登录后切到主界面的一瞬间被丢掉了），改过以后在手机那遍看到了。
- 设备测试，两台静默模拟器（手机、平板）对演示服务器：两台都是 9 项通过、各跳过二步验证那项（演示服务器没有二步验证），和 0.3.1 相同。
- 真手机上还没试。

## 已知限制

- 同一个版本号再发 `-test.2` 不会被当成新版本：发新测试版要升版本号。
- 安装要经过系统的确认，不能静默更新；第一次还要允许"安装未知应用"。
- 正式版的签名密钥还没有建；建好前只有测试版这一路。
